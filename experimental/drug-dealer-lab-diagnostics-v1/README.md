# Drug Dealer 7.3 제조실 상태 진단 v1

제조실에 갔는데 버튼과 옆 안내가 모두 보이지 않는 증상의 진단용 CET 모드입니다. 원인 수정 패치가 아닙니다.

## 사용

1. 이 ZIP을 MO2에 별도 모드로 설치하고 활성화합니다. 원본 파일을 덮어쓰지 않습니다.
2. MO2로 게임을 다시 실행하고 문제가 난 제조대 바로 앞에 섭니다.
3. 그 자리에서 CET 오버레이를 엽니다. onOverlayOpen 이벤트가 상태를 한 번 기록합니다.
4. 제조대 주변에서 조금 이동한 뒤 CET를 열면 다른 위치의 상태도 기록할 수 있습니다.
5. 게임 종료 후 bin/x64/plugins/cyber_engine_tweaks/scripting.log를 첨부합니다. 기록은 [DDLabAudit] 접두어로 구분됩니다.
6. 진단이 끝나면 이 모드를 비활성화해도 됩니다.

CET 단축키 메뉴에서 `Drug Dealer: capture lab diagnostics`를 지정해 기록할 수도 있습니다. 단축키 지정은 필수가 아닙니다.

## 기록 내용

- 플레이어 좌표와 원본 Drug Dealer 7.3 제조실 좌표 기준 가까운 3곳의 거리·감지 반경·높이 차이.
- LabInteractionController 존재 여부와 IsInteractionShown 반환값.
- 컨트롤러가 마지막으로 인식한 제조실의 감지 반경 및 좌표.
- NightlyNow 알림 시스템과 Drug Dealer 제조 시스템 존재 여부.
- 제조 상호작용 제목의 실제 번역 조회 결과.

퀘스트·인벤토리·제조 상태·좌표·설정은 변경하지 않습니다. 원본 함수는 호출해 상태를 조회할 뿐, 제조 시작·타이머 재시작·텔레포트는 하지 않습니다. 매 프레임 검사는 없고 CET를 열거나 진단 단축키를 누를 때만 조회합니다.

좌표 비교는 이전에 첨부한 원본 7.3을 기준으로 합니다. 다른 모드가 LabLocations.reds를 바꿨다면 비교 결과가 달라질 수 있습니다. read_error가 나오면 해당 공개 필드·메서드를 CET에서 조회하지 못한 것이며, 그 자체만으로 원본 모드의 실패를 의미하지 않습니다.

## 현재 확인한 로그

2026-11-05 01:53:50 시작 세션에서 RED4ext 27개 플러그인이 로드되었고 01:54:00 redscript 컴파일이 완료되었습니다. 현재 세션의 scripting.log에는 Drug Dealer 런타임 진단이 없어 제조실 감지 상태는 알 수 없습니다. NightlyNow 연락처 정렬 중복 교체 경고는 있으나 이 증상과의 직접 연관은 확인되지 않았습니다.

최신 원본 소스의 Dark Future 연동은 PrepareProduct 실행 이후의 제조 처리에 있습니다. LabInteractionController의 장소 감지 단계에는 Dark Future 직접 호출이 없습니다.

## 검증

LuaJIT에서 모의 게임 API를 사용해 파일 로드·이벤트 등록·제조실 거리 계산·공개 상태 조회와 로그 출력을 확인했습니다. 실제 게임/CET 실행은 수행하지 못했습니다.
