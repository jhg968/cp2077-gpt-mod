# AutoGorilla v0.4.4 — 최근 실제 근접 공격자도 감지

v0.4.3 최신 기록에서 실제 피격24회 중 패링11회는 모두 자동 반격으로 이어졌습니다.
놓친13회는 모두 대기 상태였고 같은 공격 상태에 가드 진입이 기록되지 않았습니다.
따라서 반격 상태를 강제로 바꾸지 않고 대상 감지 범위를 먼저 확장합니다.

## 변경과 한계
조준점 가까운 후보가 부적격이어도 즉시 끝내지 않고, 최근 실제로 근접 공격한 NPC 최대3명도 검사합니다.
상대는 피해 처리에서 관측해 플레이어에 저장합니다. v0.4.2의 NPC 콜백 후보 전달/새 NPC 필드는 복원하지 않았습니다.
NPC 상태 콜백은 v0.4.3과 바이트 단위로 같습니다.
반격 이벤트, 기본 패링 시간창, 공격 레코드, 피해 생성 경로는 바꾸지 않았습니다.
거리3m, 기본 방어 방향, 공격 상태 시작 확인, 최초0.12초, 중복/쿨다운/대기 상태 조건은 유지합니다.
최근 상대 참조에는 존재/부착/활성 및 상태 블랙보드 유효성 검사를 적용합니다.
현재 조준점 후보에 대한60도 카메라 필터는 유지합니다. 최근 공격자에는 기본 방어 방향 검사를 사용합니다.
새 상대는 실제 근접 접촉 전에는 기억되지 않습니다. 첫 공격부터 모두 잡는 기능은 아닙니다.
아직 모든 원인의 누락이 계측된 것은 아니므로 이 수정으로 성공률이 올라간다고 보증하지 않습니다.

## 설치와 확인
1. 게임을 종료하고 이전 AutoGorilla와 별도 NativeTrace를 모두 비활성화합니다.
2. AutoGorilla-v0.4.4-native-first.zip을 MO2에 별도 모드로 설치하고 이 버전만 활성화합니다.
3. 우선 고릴라 암을 꺼낼 수 있는지 확인합니다. 종료되면 반복하지 말고 비활성화하세요.
4. 장착이 정상이라면 추가비용0 / 최소간격0.3초 / 배율1 / 진단로그 켜기로 같은 상대와 약20초 비교합니다.
5. 실제 반격/적 피해와 성공률 변화를 알려주고 AutoGorilla.log를 보내주세요.
CET/redscript/Native Settings UI는 유지하고 MO2를 통해 실행합니다.
설정은 Mods → AutoGorilla에 있습니다. 기존 settings.json은 보존하거나 다시 설정하세요.

## 로그
AUTO remembered actual melee attacker: 실제 접촉에서 상대를 기억함.
sensor=fresh_recent_attacker: 기억한 상대가 이번 방어 준비 대상으로 선택됨.
기존 기본 패링/반격/공격 생성/실제 피해 이벤트 및 TIMING 추적도 유지합니다.
전용: bin/x64/plugins/cyber_engine_tweaks/mods/AutoGorilla/AutoGorilla.log
공통: bin/x64/plugins/cyber_engine_tweaks/scripting.log
컴파일: r6/logs/redscript_rCURRENT.log
MO2 Overwrite에도 있을 수 있습니다.

## 검증
41개 wrapper 선언 대조, NPC 콜백 변경 없음 확인, 구분자/ZIP 무결성 검사를 수행했습니다.
실제 게임용 컴파일, 새 후보 선택과 장착 안정성/성공률은 아직 미검증입니다.
개인 로그 원문/경로/게임 및 기반 모드 파일은 공개 배포하지 않았습니다.

기본 구조: 피격 전에 기본 Deflect 진입만 준비하고 이후 성공/반격/피해는 원래 게임 경로를 사용합니다.
가짜 패링 플래그/성공 이벤트 억제/피격 보류/별도 가짜 반격은 없습니다.
고릴라 암 대기 상태가 대상이며 공격/회피 중 발동 범위는 확대하지 않았습니다.
카타나/다른 무기/총알 반사는 아직 구현하지 않았습니다.
v0.4.2는 계속 사용 중단 상태입니다.
